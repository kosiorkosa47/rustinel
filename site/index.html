The supply-chain attack exists before the CVE does.

rustinel is a static, offline-first risk scanner for Cargo dependencies — a pull-request firewall that catches maintainer takeovers, typosquats, secret-exfiltration code and hidden payloads while they are still invisible to advisory databases. And it matches cargo audit advisory-for-advisory on the ones that aren't.

The gap

Advisory scanners look backwards. Attacks happen forwards.

An advisory database is a list of incidents that already happened, got noticed, got triaged and got published. Every supply-chain attack has a window — days to years — where it is live and no database knows it. rustinel is built for that window, and composes with the tools that aren’t.

Pre-CVE detectors

Ten signals for attacks that don’t have a name yet.

Every detector is static and read-only: rustinel never executes, never compiles, never loads the code it analyzes. Each finding carries evidence, a confidence score and the dependency path that pulls the crate into your tree.

takeover

owners_changed

The owner set of a trusted crate changed against your recorded baseline. The xz and event-stream vector — a maintainer handover is invisible in the code and in every advisory feed.

takeover

freshly_published

The locked version went live days ago. New means unreviewed — the publication window is where every compromised release does its damage.

impersonation

possible_typosquat

A name one edit away from a popular crate, corroborated against download counts so look-alikes with real adoption stay quiet. Catches Unicode homoglyphs (serdе with a Cyrillic е) that byte-level checks can’t see.

impersonation

source_substitution

A popular crate name resolved from a source that is not crates.io — the dependency-confusion shape, including a lockfile that silently redirects one pinned version to a git repo.

malicious code

suspicious_source_exfil

Runtime source that scans your project’s own files and reaches the network or handles wallet-key formats. The fingerprint of the faster_log / async_println crypto-stealers.

malicious code

suspicious_exfil_domain

Hard-coded exfiltration endpoints — *.workers.dev, webhook.site, pastebin, ngrok and friends. Dual-use services (Telegram API, Discord webhooks) only fire with same-file secret handling, so bots and notifiers stay clean.

malicious code

env_gated_payload

Code that only detonates under CI environment variables — read env, fetch, execute, all within a tight window. The rustdecimal pattern (2022): payloads built to hide from a laptop and fire in CI.

malicious code

obfuscated_payload

A large embedded base64/hex blob that gets decoded and fed to a process spawn or dynamic loader. A blob decoded into data — a cert, a fixture — is not flagged; the execution sink is the discriminator.

build time

build_script_suspicious

A build.rs that reaches the network or unpacks an opaque payload — scanned statically, never executed. Legitimate cc-style native builds are not flagged.

policy

denied_crate

An operator deny list that can never silently no-op: matched across -/_ name variants and enforced on git and path dependencies too.

And the baseline a scanner must have: RustSec advisory matching (full cargo-audit parity, v4 database, offline cache) · yanked versions · license detection with SPDX expression evaluation and allow/deny policy · unsafe usage counts · native/FFI surface · duplicate versions · lockfile-poisoning diff (a redirected source or swapped checksum on an unchanged version) · a dependency path on every transitive finding.

The PR firewall

Risk review where dependencies actually change: the pull request.

.github/workflows/supply-chain.yml 
permissions:
  contents: read
  pull-requests: write
jobs:
  supply-chain:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - run: |
          git show "origin/${{ github.base_ref }}:Cargo.lock" \
            > base.Cargo.lock || cp Cargo.lock base.Cargo.lock
      - uses: kosiorkosa47/rustinel@v0
        with:
          command: diff
          base-lockfile: base.Cargo.lock
          head-lockfile: Cargo.lock
          policy: rustinel.toml
          online-metadata: "true"
          # also file findings on the Security tab:
          # code-scanning: "true"
  • Sticky PR commentRisk delta, decision and the findings that caused it — created once, updated in place on every push. Advisories and pre-CVE signals are listed in separate sections, so reviewers see what cargo-audit would have said and what only rustinel sees.
  • Policy as the gateThe exit code is driven by your rustinel.toml — three built-in profiles (strict / balanced / permissive), severity ladders, license allow/deny, crate deny lists, risk-delta thresholds.
  • Code-scanning alertsOpt-in SARIF upload turns findings into tracked alerts on the repository’s Security tab — with stable fingerprints, so an alert resolves when fixed instead of churning.
  • Pinned installA version-tagged action ref installs exactly that version; any other ref builds from the exact pinned commit. The supply-chain scanner is not itself a supply-chain risk.

Policy

Your rules, enforced — never silently relaxed.

rustinel.toml 
version = 1

[profile]
name = "balanced"   # strict | balanced | permissive

[risk]
max_project_score   = 70
fail_on_delta_above = 35

[advisories]
fail_on = ["critical", "high"]

[licenses]
deny = ["GPL-3.0", "AGPL-3.0"]

[deny]
crates = ["leftpad-rs"]
  • Fail-closed by designA malformed SPDX expression containing a denied license is denied. An advisory severity your policy forgot to list surfaces as a warning instead of vanishing. A misspelled profile name is a hard error, not a silent downgrade to defaults.
  • Severity that means somethingCVSS v3.x vectors are computed per the first.org specification, so a 9.8 drives your critical rule — and risk scoring uses diminishing returns per signal class, so thirty -sys crates don’t drown one exfil finding.
  • Explainable--explain prints the live score breakdown; every decision lists the exact violations, review items and warnings that produced it.

Security model

A supply-chain tool must not be a supply-chain risk.

rustinel never runs build.rs, never runs cargo build on an analyzed project, and never loads or executes dependency code. Analysis is static, read-only and offline-first.

Offline by default

Advisory matching runs from a local cache. The only network feature, --online-metadata, is opt-in — and a build with --no-default-features contains no HTTPS client at all.

SSRF-proof lookups

Online metadata queries go to a fixed host with validated crate-name paths and redirects disabled. No request target is ever derived from analyzed data.

Hostile-input hardened

Every parser that touches untrusted input — lockfiles, manifests, sources, advisories — is panic-guarded and continuously fuzzed across 8 nightly targets.

Bounded everything

Size-capped reads (oversized files are scanned as a prefix, never skipped), depth- and entry-bounded directory walks, symlinks never followed.

Injection-safe output

PR comments, SARIF and terminal output escape untrusted text — including Trojan-Source bidi overrides and zero-width characters.

Loud degradation

A failed online lookup, a partial result, a capped walk — every degraded answer says so. No silent fail-open paths.

Quick start

Scanning in under a minute.

1 · Install

# from crates.io
cargo install cargo-rustinel

# prebuilt binary, no compile
cargo binstall cargo-rustinel

# zero network dependencies
cargo install cargo-rustinel \
  --no-default-features

MSRV 1.86 · Linux, macOS, Windows

2 · Scan

# one lockfile
cargo rustinel check \
  --lockfile Cargo.lock

# how does this PR change risk?
cargo rustinel diff \
  --base-lockfile base.Cargo.lock \
  --head-lockfile Cargo.lock \
  --format markdown

Formats: human · json · markdown · sarif

3 · Gate & export

# starter policy
cargo rustinel policy init \
  --profile balanced > rustinel.toml

# sync the RustSec database
cargo rustinel advisory update

# compliance artifacts
cargo rustinel export \
  --format cyclonedx

Exit code is policy-driven: fail → 1
